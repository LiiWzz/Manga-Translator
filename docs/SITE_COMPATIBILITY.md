# Site compatibility

Reader translates English manga dialogue into Thai. These changes expand site compatibility through explicit CDN grants and a manual screenshot crop flow; they do not claim universal website or language support.

| Source layout | Read path | Limits |
| --- | --- | --- |
| Loaded visible `<img>` / `<picture>` in the main document | **แปลภาพที่เห็น** | Existing size/visibility filters; up to three images per click. |
| Image on any additional HTTPS CDN | Approve **อนุญาตรูปจาก …**, then retry that image | One origin per prompt; cookies omitted; redirects rejected. Cross-origin HTTP images are rejected. |
| Canvas, CSS background, `blob:` or `data:` image | **เลือกพื้นที่แปลจากหน้าจอ** | Screenshot resolution; only the currently visible portion. |
| Images inside shadow DOM or iframes | Screenshot crop | Does not inject scripts into embedded frames. |
| Redirecting or authenticated image endpoint | Direct request may fail | No credentialed or proxy fallback; only authorized content may be captured manually. |
| Protected/unavailable content or browser-restricted capture | Unsupported | No access-control bypass or all-sites permission escalation. |

## Screenshot crop flow

1. Open an authorized HTTP/HTTPS manga page. Position and zoom the desired content on screen.
2. Click the extension toolbar icon on that tab, then **เลือกพื้นที่แปลจากหน้าจอ**. If capture fails, Reader explains how to grant temporary capture access by clicking the toolbar icon again.
3. The full screenshot appears only in the extension preview. Initially the entire screenshot is selected. Drag to choose a smaller area, or use **เลือกทั้งภาพ**. Keyboard users can focus the selection surface, use Shift + arrow keys to resize, arrow keys to move, and Escape to cancel.
4. Check the outlined region and dimensions, then click **ส่งพื้นที่ที่เลือกแปล**. Only those pixels are encoded and submitted to the existing Reader endpoint. No inference occurs merely from opening the preview or adjusting it.
5. Cancel, reset, navigation or switching the source tab discards the preview. Confirmation revalidates the source even if a tab event was missed. Reopen capture to take a fresh screenshot after scrolling or changing content.

Preview is limited to 24 MP / 32 MiB of encoded screenshot data. A submitted crop must be at least 16 × 16 pixels and at most 8 MiB of decoded image-file bytes. Backend image and model limits still apply. PNG encoding avoids additional browser compression artifacts; screenshot capture cannot restore detail lost by displaying a scaled image. Original-image coordinate selection remains future work.

Screenshots never go into persistent storage. The preview is released on close; the latest three failed crops may retain their cropped bytes in panel memory for explicit retries. An older failed crop may require a fresh capture. Successful translations release the crop bytes. Dialogue, model provenance and corrections use the existing bounded cache; confirmed crops and bounded dialogue context are sent to the configured provider in real mode. Mock mode produces demo text.

## Permissions and request behavior

The manifest is unchanged: no new mandatory permission or origin expansion. Source-page access and image access use exact-origin prompts under the existing optional HTTP/HTTPS patterns. The user reviews each additional origin before it is fetched. A CDN error cannot request an unrelated domain. Permission denial submits no retry; stale grants cannot resume an old chapter.

Capture uses Chrome's existing `activeTab` permission, granted through a toolbar invocation. A click inside the persistent Side Panel alone does not grant it. Capture requests accept only the trusted extension Reader page and validate the active source before and after capturing. Captures of browser UI, files and other non-HTTP(S) URLs are rejected by Reader even where Chrome itself could allow them.

Chrome references: [captureVisibleTab permissions](https://developer.chrome.com/docs/extensions/reference/api/tabs#method-captureVisibleTab), [activeTab](https://developer.chrome.com/docs/extensions/develop/concepts/activeTab).

## Validation and acceptance

Automated regressions cover exact-origin CDN grants/denials, request cookies/redirect policy, stream byte limits, unsupported sources, trusted capture callers, crop geometry, keyboard selection, cancel/reset/navigation races, stale permission grants, retry, cache reuse and corrections. Fixtures use generated bytes and mocked Chrome APIs, without provider calls or licensed manga assets.

A BrowserOS neo preview using generated artwork and mocked Chrome messaging verified a 390 × 844 panel: dragging selected an 800 × 500 crop, the encoded submitted PNG decoded to those dimensions, the preview was discarded, and cancellation left the submission count unchanged. This checks real DOM/canvas behavior; it does not test installed-extension capture or Chrome permission prompts.

Before merge, exercise the unpacked extension in desktop Chrome on authorized sources:

- A same-origin image and at least two distinct CDN origins; verify Chrome prompts for only the displayed domain, and that denial/revocation leaves fetching blocked.
- A generated canvas/background/iframe page; verify toolbar-granted capture, visible crop alignment at different zoom levels/display scaling, cancellation, and no inference before explicit confirmation.
- Switch tabs, navigate, scroll and reset during capture/translation; confirm old work does not submit remaining images or restore stale results.
- Verify image/crop cache reuse, corrections, gateway-offline errors and real-account translation quality separately. Automated and local preview evidence does not establish compatibility with all websites.
